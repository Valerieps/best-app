# ADR-058: CI runs the build on pull requests; no dev branch

**Date:** 2026-10-16
**Decision:** A GitHub Actions workflow (`.github/workflows/ci.yml`) runs `npm ci` and `npm run build` (typecheck, unit tests including `src/security.test.ts`, production build) on every pull request and on every push to `main`, on Node 24. A pull request is merged only after its "CI / build" check passes. There is no `dev` branch: changes go from short-lived branches (one per agent session, each in its own worktree) straight to `main`, and Cloudflare Pages' preview deployment of each branch serves as the staging environment. Branch protection that would enforce the check on `main` is not available on a private repository under GitHub's free plan, so for now the rule is a convention agents follow (`gh pr checks --watch` before merging).
**Why:** Before this, the build ran only in the agent's worktree before merging and in Cloudflare Pages after merging. The first tests the branch alone, not the result of merging it with a `main` that other sessions moved meanwhile; the second only stops the deploy, with the broken code already on `main`. This happened once: a closing brace lost while merging parallel pull requests (commit `fc4224e`). A `dev` branch would add one more merge per change and more conflicts between parallel sessions, without adding a check that the pull request build and the preview deployments do not already give.
