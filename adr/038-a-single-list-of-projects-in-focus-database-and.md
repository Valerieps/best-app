# ADR-038: A single list of projects in focus; database and backup version 7

**Status:** Accepted, updated by ADR-060
**Date:** 2026-10-12
**Decision:** The projects in focus (up to 3) are one record in `priorities`, id `focusProjects`, scope `focusProjects`, with no period. Use cases in `application/focusProjects.ts`: `addFocusProject` takes a free slot outside the review; `setFocusProjectInReview` adds or removes freely in the Revisão de Foco; `releaseFocusProject` runs inside `setProjectFinished`, so reopening does not bring the project back. Each change records `priority.added` or `priority.removed` on the entity `focusProjects`, with `{ projectId, itemIds }`, plus `reason: 'review' | 'finished'` on removals. Since every event carries the whole list, the history comes from the events: `focusProjectsOnDay` gives the list in focus at the end of any day, for the raio-x, and `focusListEmptied` tells whether finishing the last project emptied the list (a signal of the Revisão de Foco; a removal in the review does not count). Migration: database version 7 (Dexie `upgrade`) and `BACKUP_SCHEMA_VERSION` 7 (`parseBackup`) both run `migrateToFocusList`, which starts the list in focus as the week list in effect on the current day (for a backup, the day it was exported). A list that a reflection had already set for a later week is dropped. The week lists (`weekProjects:AAAA-Www`) stay in the table untouched, read only by `focusProjectsOnDay` for the days before the first change of the list in focus. `loadProject` no longer takes `today`.
**Why:** The spec replaced the projects of the week with the projects in focus, valid until the next Revisão de Foco (spec/prioridades.md, "Projetos em foco"), so carry-over between weeks, the copy to a "next week" and the per-week lists lost their reason. Keeping the old week lists instead of rewriting them into events keeps the past raio-x as it was recorded without inventing events. Recording the reason of a removal is the only way to tell a finish from a review choice later, from the events alone.
**Supersedes:** ADR-035 (the version 6 migration from month to week lists still runs for older data).
**Update (2026-10-17, ADR-060):** the Revisão de Foco is gone. The list in focus changes at any time: `removeFocusProject` (reason `removed`) and `swapFocusProject` (one `priority.added` with `replaced`) replace `setFocusProjectInReview`, and nothing reads the history of the list for the raio-x anymore.
