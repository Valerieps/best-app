# ADR-042: Screens fail alone, and live queries report their errors

**Status:** Accepted
**Date:** 2026-10-13
**Decision:** The screens in `App` sit inside an `ErrorBoundary` (`ui/components/ErrorBoundary.tsx`) keyed by the route, so a screen that fails to draw shows `ScreenError` ("Algo deu errado nesta tela", "Tentar de novo" and a way to "Dados e backup") while the sidebar keeps working, and moving to another screen starts clean. A second boundary around `App` in `main.tsx` shows `AppError` with "Recarregar" when the shell itself fails. `useLiveQuery` no longer turns a failed query into `undefined`: it logs the error to the console and throws it while rendering, so the screen's boundary shows it. The shell (the `App` warnings and stage, the sidebar counts and settings, the due reminders, and the details of "Dados e backup") uses `useLiveQueryState`, which logs the error and returns `{ value, error }`, so a failing extra never takes down navigation or the way to the backup; when the day's stage cannot be read, the day note opens. Errors only go to the console: there is no telemetry (`SEGURANCA.md`).
**Why:** Without a boundary, any exception blanked the whole app, "Dados e backup" included, and a failed query left a screen on its skeleton forever with nothing in the console (a known limitation as of 2026-10-12). Keying the boundary by route makes leaving the broken screen the natural way out. Keeping the shell on the non-throwing variant leaves the sidebar and the backup reachable in every failure that a boundary can catch.
