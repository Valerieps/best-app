# ADR-070: Remove the project next steps; the project page shows the queue

**Status:** Accepted
**Date:** 2026-11-12
**Decision:** The "Próximo" mark on a task (ADR-065) is gone: `domain/nextSteps.ts`, `application/nextSteps.ts`, every `releaseNextStep` call, the "Próximo" action and chip, the task list's "Só próximos passos" filter and `nextStepIds` on `ProjectView` and `TaskListContext` were removed. The project page's "Próximos passos" group became "Na fila": `groupProjectTasks(active, today, queueIds)` takes the ids of the "Fila de execução" (ADR-069) and returns `queued`, the project's tasks in the queue's order, with the same rule as before (a stuck task stays only among the stuck ones, a queued one leaves "Sem data"). The page already loaded the queue ids for "Adicionar à fila", so no new query. Stored `next:<projectId>` lists and their `priority.added` / `priority.removed` events stay in the database and the backup as history, untouched: no migration, no database or backup version change, and the `nextSteps` scope stays in the `PriorityList` type so old records still type-check. The task list's saved view in `localStorage` may still carry `nextOnly`; `readView` ignores it.
**Why:** The owner replaced the concept with the execution queue (spec/prioridades.md, "Fila de execução"): one place to choose what to do next, across projects, instead of a per-project mark of up to 3. Keeping the old records as history follows the append-only event log and the way the week lists were kept (ADR-035); deleting them would need a migration for no gain, since nothing reads them.
