# ADR-057: Ctrl + K place palette and its conflict with the day note's link shortcut

**Status:** Accepted
**Date:** 2026-10-16
**Decision:** `PlacePalette` (`src/ui/components/PlacePalette.tsx`) is mounted next to the sidebar in `App.tsx`, so it exists exactly on the screens that have the sidebar (also focus mode and "Fechar o dia", never "Iniciar Dia"). It listens to `keydown` on `window` in the bubble phase and opens only when the event was not `defaultPrevented`. The day note's lines already prevent the default of Ctrl + K when they format a link (ADR-048), and React's root listener runs before `window`'s, so inside a day note line Ctrl + K stays the link shortcut and anywhere else (other fields included) it opens the palette and stops the browser's own Ctrl + K. The box is a native `<dialog>` opened with `showModal()` (focus trap, Esc, backdrop) holding a combobox input and a listbox with `aria-activedescendant`; focus returns to the element that had it. The places and the matching logic are pure functions in `src/ui/placePalette.ts`: the sidebar's places in its order, matched as a case- and accent-insensitive substring, names that start with the query first.
**Why:** The owner wanted Ctrl + K only to navigate among the sidebar's places (issue #119). Checking `defaultPrevented` lets the editor keep its shortcut without the palette knowing about the editor. The places list is duplicated from `Sidebar.tsx` instead of shared, to keep this change out of a file another session was rewriting; the sidebar can adopt `palettePlaces` later.
