# ADR-050: No wiki; kept notes stay in their sections, edited and deleted on the project page

**Status:** Accepted
**Date:** 2026-10-15
**Decision:** The wiki screen, its `#/wiki` route, its sidebar entry and the `wikiInSidebar` flag are gone, and so is `discardWikiNotes`. The stored model does not change: when a day closes, a section's `notesDestination` still becomes `wiki`, which now only means "the day closed and the notes are kept", and the event `section.notesMovedToWiki`, the triage item `notesToWiki` and `Reader.wikiSections` keep their names. `discarded` and `section.notesDiscarded` stay valid for older data. The query behind the old screen is `loadSectionNotes` (`SectionNotes` entries), and the project page reads its "Notas" tab from it. That tab (`ui/projects/ProjectNotes.tsx`) edits a note with `updateBlockText`, deletes one with the new `deleteKeptNote` (notes only, any day, recording `block.deleted` with the text) and links a section's notes as a resource with `linkSectionNotesAsResource`, the renamed `linkWikiNotesAsResource`.
**Why:** The owner decided there is no reason to centralize notes without a link to a project (spec/nota-do-dia.md, "Notas depois do dia"). Renaming `wiki` in stored records and events would need a database and backup migration plus a new event version (ADR-043) for no change in behavior, so only the names the UI and the use cases expose changed. `deleteBlock` stays limited to untriaged lines written today, as an editor delete; deleting a kept note is a separate, deliberate action, so it gets its own use case instead of loosening that guard.
