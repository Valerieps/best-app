# ADR-044: The checkout saves each step when moving on

**Date:** 2026-10-14
**Decision:** The checkout is a sequence of steps (`src/domain/checkoutSteps.ts`): whiteboards, "Fez e não marcou?", tasks needing attention, reminders, the confirmation and the planning. Which steps exist is computed once, when the screen opens, from the triage and the pending reminders, and a step with nothing to decide is left out. Each step applies only its own decisions when the user moves on, through the existing `applyTriage` (in one transaction) or the reminder use cases, then the screen reads the triage again and moves to the next step that still has items; going back also skips steps left empty. The confirmation applies what is left, including the automatic decisions, as before (ADR-012). Reopening the checkout computes the steps again, so it starts at the first step still pending. The planning applies dates per task (`applyPlanning` takes `{ taskId, date }`), so it can also move tasks already scheduled; the batch selection lives only in the screen until "Finalizar meu dia".
**Why:** The owner chose to keep what was decided when leaving halfway (spec/checkout.md, "Checkout em etapas"). Reusing `applyTriage` with partial maps needed no new use case: a decided task gets `lastTriagedDay` and a decided whiteboard leaves the pending state, so the next reading of the triage no longer lists them. Freezing the list of steps at opening keeps the stepper stable while steps empty out under the user.
