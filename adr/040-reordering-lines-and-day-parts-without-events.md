# ADR-040: Reordering lines and the parts of a day, without events or a schema version

**Date:** 2026-10-13
**Decision:** Moving a line inside a section writes only that block's `position`, a fractional index between its new neighbors (`placeInOrder` in `domain/order.ts`); if the neighbors have no key or repeated keys, every line of the group gets a new one. Tasks carried from other days keep their own order in `Block.carriedOrder = { day, position }`, which counts only while `day` is the task's intended date, so a task moved to another day loses it without any code touching the date paths; tasks without an order for the day come last, by creation (`sortCarried`). The parts of a day note (its sections, the carried tasks under the key `carried`, the priorities under `priorities`, and the day's unsaved first section under `first`) are ordered by a list of keys in `DayRecord.sectionOrder`, one per day; `orderDayParts` puts parts missing from the list first (priorities, carried tasks, the first section) or last (new sections) and drops keys no longer shown. Saving the first section replaces `first` with its id (`adoptFirstPart`), and the checkout keeps `sectionOrder` when it rewrites the day record. The day note and the triage (`buildDayNote`, `buildDayTriage`) read both orders. No event is recorded for a reorder, and neither the database nor the backup version changes: the fields are optional, absent on old records, and travel in the backup as part of their records. The screen shows a new order at once and saves it through the write queue (`ui/writeQueue.ts`), after the writes already queued; dragging uses pointer events (`ui/dayNote/lineDrag.ts`), not the HTML drag and drop API.
**Why:** Order is presentation, not history: no metric in the spec depends on it, as with plain text edits (ADR-004). One record per move keeps a move cheap and conflict-free with the rest of the editor. A per-day list fits parts that are not records (the priorities, the carried tasks) and the rule that each day keeps its own order (spec/nota-do-dia.md, "Ordem das linhas e das seções"). Pointer events also work with a finger, which the HTML drag and drop API does not do reliably.
