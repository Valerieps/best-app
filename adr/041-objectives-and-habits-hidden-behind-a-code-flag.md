# ADR-041: Objectives and habits hidden behind a code flag

**Status:** Accepted, updated by ADR-060
**Date:** 2026-10-13
**Decision:** `ui/features.ts` holds `FEATURES = { objectives: false, habits: false }`, changed only in code. With a flag off, the interface hides everything that depends on the feature: the sidebar items, the screens (`enabledRoute` opens the day note instead of `#/objetivos`, `#/objetivos/…`, `#/habitos` and `#/rumo`), the objective of a project (menu, side panel, focus card), objectives as resource owners in the checkout, "Virar hábito" in the checkout, the habits on the dashboard and in the Revisão de Foco. The Revisão de Rumo follows the objectives flag (`directionReviewEnabled`): it leaves the "Rituais" list, its cadence leaves the settings, and `visibleReviews` empties its availability, so it neither counts in "Rituais" nor raises the notice. Only the interface changes: domain, use cases, queries, events, the database and backups keep everything, and data already linked to objectives or habits stays as it is.
**Why:** The owner asked to hide objectives and habits until their spec is finished (13/10/2026), hiding everything that depends on them, with the Revisão de Rumo going with the objectives, and bringing them back with a change in code rather than a setting. Keeping the hiding in the interface leaves the tested behavior intact and makes turning them back on a one-line change.
**Update (2026-10-17, ADR-060):** the Revisão de Rumo is no longer hidden behind the objectives flag: it left the app, and `directionReviewEnabled` and `visibleReviews` with it.
