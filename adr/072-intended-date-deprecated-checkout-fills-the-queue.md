# ADR-072: The intended date is deprecated; "Fechar o dia" fills the execution queue

**Status:** Accepted
**Date:** 2026-11-12
**Decision:** A task of mine no longer gets an intended date from the UI. The field `intendedDate` (and `firstIntendedDate`, `carriedOrder`) stays in the data model, the backup format and the database version: no migration, no new database version. What changes:

- **UI.** No "Data" chip or hover action on task lines (`BlockLine`), in the priorities block, the task table (column, group by and sort by intended date, batch date) or the people screen. The priorities block lost its move countdown (`pendingMoves.ts`, `moveDayPriority`). A waiting task keeps its follow-up date ("cobrar"), stored in the same field (ADR-052).
- **Checkout.** The steps are `triage` and `reminders`; the "late" board and the day columns are gone (`loadPlanning`, `planningColumns`, `planningColumnOf`). The board has two columns: the tasks of the day and the "Fila de execução". A new `TaskDecision` `{ kind: 'queue' }` clears any old date quietly (no postponement) and adds the task to the end of the queue with `queueIn`, the transactional core of `addToQueue`. Tasks already in the queue show in its column and are not moved. A task left untouched keeps its suggestion (`undate` untouched, or `keep` for a waiting task), so an old date is cleared without counting as postponed.
- **Removed.** The "Tarefas esquecidas" assistant (`findForgottenTasks`, `resolveForgottenTasks`, `planForgottenTasks`, its UI, route slug and the `forgottenTaskDays` setting field in the UI; `COUNTED_ASSISTANTS` went with it, since it was the only counted assistant). The "travada" concept (`isStuckTask`, `stuckReason`, `stuckTasks` in the project list). The project page groups are now `queued`, `open` ("A fazer") and `waiting`, each by creation.
- **Kept on purpose.** `setIntendedDate`, `moveIntendedDate`, the `schedule` decision and `applyPlanning` stay in the application layer: the waiting tasks' follow-up date uses the first two, and the synthetic data replays a history in which tasks had dates. Old saved `forgottenTaskDays` and `cleanupAgeLimits.forgottenTasks` values are ignored, not cleaned.

**Why:** The owner decided that choosing what to do is putting it in the queue, not giving it a day; dates kept piling up and being pushed forward. Keeping the field avoids a database version for a value that old tasks still carry and that the follow-up date of waiting tasks still needs. For new work, it replaces the date boards of the checkout and the date parts of ADR-015 and ADR-049.
