# ADR-049: People are records, mentions are read from the text, and a waiting task reuses the intended date

**Date:** 2026-10-15
**Decision:** A person (`spec/pessoas.md`) is a record of its own in a new `people` table (`id`, `name`, `status` `active` | `archived` | `merged`, `mergedInto`), which takes database and backup version 8. A mention is not stored apart: `@Nome` stays in the block's `text`, and `domain/people.ts` reads it every time (one word of letters, digits and `_`, after the start or a character that cannot be part of a name, so an e-mail is no mention; case-insensitive, accent-sensitive). Renaming or merging people rewrites the text of every line that cites them, found by `blocksWithMentions()` (every block whose text has an `@`), with no event per line (ADR-004). A task's person is the first person it cites. People are created when I leave a line, or choose "Criar a pessoa…", never on each save, so a half-typed name never becomes a person; only names typed since the line got the focus are created, so a deleted person does not come back by just clicking an old line.

A waiting task ("aguardando", "[a] ") is a regular task with `waiting: true`. Its follow-up date ("data para cobrar") is its `intendedDate`, so it shows up in the day note on that date and is pending at the closing by the rules that already exist (`isTaskPendingOn`). What changes for it: moving the date is no postponement (`moveIntendedDate`, "Fechar dias pendentes"); the closing asks about it instead of rolling it over, with the new decision `keep`; it stays out of the active tasks, the planning and the stuck tasks; and `task.finished` carries `waiting: true`, so the intention accuracy leaves it out. Marking a task as waiting, or back, records `task.waitingChanged`.

**Why:** Reading mentions from the text keeps one source of truth: a line edited anywhere (the day note, the project page, another tab) needs no second write to stay linked, and backups stay readable. An index of mentions would have to be kept in sync with every edit and every new person. Scanning the blocks that have an `@` is cheap for one person's data, like the other metrics computed in the app (`spec/principios.md`). Reusing `intendedDate` for the follow-up date gives the waiting task the day note, the closing and the date pickers for free, and keeps the follow-up dates out of the postponement and accuracy metrics through one flag instead of a second date field that every screen would need to learn.
