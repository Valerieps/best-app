# ADR-055: Dark theme tokens, and the appearance setting mirrored in localStorage

**Status:** Accepted
**Date:** 2026-10-16
**Decision:** The dark theme is a second set of values for the color tokens in `tokens.css`, written twice with the same values: under `@media (prefers-color-scheme: dark)` for `:root:not([data-theme="light"])`, and under `:root[data-theme="dark"]`. Each block also sets `color-scheme`, so native controls and scrollbars follow. Components keep naming tokens only; the shadows and the dialog backdrop that were literals in `global.css` became tokens (`--color-shadow-soft`, `--color-backdrop`). In dark, the brand is a lighter lilac (`#a99cf5`, 6.9:1 on the surface) and `--color-accent-text` turns dark (7.5:1 on the brand), so every filled action stays readable; muted text, status colors and banners stay above 4.5:1, and the activity map runs from the darkest cell to the lightest lilac. The choice is `Settings.appearance` (`'light' | 'dark'`; absent means the system's, the default), saved in IndexedDB like the other interface choices and carried by the backup. `src/ui/theme/appearance.ts` applies it by setting `data-theme` on `<html>`, or removing it for the system's, and mirrors it in `localStorage` (`best-app:appearance`). `src/main.tsx` applies that copy before React renders; `App` then applies the value read from the settings, which wins, including after importing a backup. Storage access is wrapped in try/catch: when it is blocked, the theme still applies and the next load starts with the system's.
**Why:** The owner wants to pick light, dark or the system's appearance (spec/principios.md, "Aparência"). Reading IndexedDB is asynchronous, so a dark choice would first paint light; the synchronous `localStorage` copy avoids that flash, and keeping IndexedDB as the source keeps the choice in the backup. Redefining tokens, not components, follows ADR-054. Duplicating the dark values is the price of supporting both "system" and a forced choice without `light-dark()` or CSS nesting; a comment in `tokens.css` asks to keep the blocks in sync.
