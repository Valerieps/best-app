# ADR-067: Ideas are blocks of kind `idea`, with a hidden section as their page

**Status:** Accepted
**Date:** 2026-11-10
**Decision:** An idea (`spec/ideias.md`) is stored as a block, and what I write about it lives in a section that belongs to no day note:

- **A block kind, not a table.** `[?] ` makes a line `kind: 'idea'` (`ideaDetector` in `domain/blockKind.ts`), next to `task` and `note`. The idea is a line of the day note like the others: it is written, moved, edited, tagged and mentioned with the same code. It takes the project of its section, or of its tag, like a task (`followsSection` in `domain/projectTags.ts`); linking a section to a project, or taking it back to a whiteboard, moves its ideas too, as it moves its tasks. Merging projects already moves every block of the merged project.
- **Idea fields on the block.** `ideaStatus` (`open`, `becameProject`, `dropped`), `notYetCount`, `lastNotYetAt` and `ideaSectionId`, all optional, absent on other kinds. `status` stays task-only, so every reader that asks `kind === 'task'` or `status === 'active'` (task list, priorities, next steps, the closing, people, metrics) leaves ideas out without a change. Two writers that did not check the kind now do: `setDayPriority` ignores a block that is not a task.
- **The page is a hidden section.** The first line written on an idea's page creates a section with `ideaId` set (and `projectId: null`, `notesDestination: 'wiki'`, `whiteboardDecision: 'keptUnlinked'`), and the idea keeps its id in `ideaSectionId`. Like the sections of a project page (ADR-031), it is left out of the day note, the closing and the assistants by `isDaySection`, and out of the kept notes (`loadSectionNotes`). It has no project on purpose: its notes are the idea's, not the project's "Notas" tab. A task or idea written there takes the idea's project when written (`addIdeaLine`, `changeIdeaLineKind`); later changes of the idea's project do not move them, as with the tasks of a section. Tasks written there count as decided today (`lastTriagedDay`), since no closing shows them. The page reuses the day note's line editor (`BlockLine`), with the kept-note writes of the project's "Notas" tab for notes (split, merge, paste).
- **One event per destination**, recorded on the idea's block: `idea.becameTask` (`projectId`), `idea.becameProject` (`projectId` of the new project, `fromProjectId`), `idea.dropped` and `idea.notYet` (`count`). "Virar tarefa" changes the block's kind in place, so the task keeps the idea's id and history; its `lastTriagedDay` becomes today, so it never reopens the closing of the day it was written in. "Virar projeto" creates the project with `fromIdeaId` and `fromProjectId` (also on `project.created`), turns the idea's section into a `projectNote` section of the new project and links it there with `linkSection`, which moves its untagged tasks; the idea stays a block with `ideaStatus: 'becameProject'`. Only an open idea takes a destination.
- **Version 11.** Blocks get an index on `kind`, so the list of ideas and the menu count read `where('kind').equals('idea')` instead of scanning every block. The same version turns the notes written with `[?] ` before ideas existed into ideas (`noteToIdea`), with the tag's project or else the section's, in the Dexie upgrade and in its twin in `backup.ts` (ADR-059). No event is recorded by the migration (ADR-049).
**Why:** A separate `ideas` table would need its own editor, its own order inside a section and its own tag and mention code, and an idea would stop being a line of the day note where it was captured. As a block kind it costs a few kind checks, and the readers that already filter on `kind` exclude it for free. The hidden section repeats a shape that already works for project pages and project notes, and gives the idea's text a real editor without a second one.
**Not done here:** the review of the ideas (step 5 of the phase 7 order, `ROADMAP.md`), which will read `notYetCount`, `lastNotYetAt` and the dates of the lines on the idea's page.
