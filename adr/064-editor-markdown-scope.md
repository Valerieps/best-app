# ADR-064: Markdown scope of the day note editor

**Status:** Accepted
**Date:** 2026-11-04
**Decision:** Supported, per line: headings 1 to 4, blockquote `> `, bullet and numbered lists, `**bold**`, `_italic_`/`*italic*`, `~~strikethrough~~`, `` `code` `` (content literal), links, and a backslash escape for `\ * _ [ ] ( ) ` ~ @`. Not supported, on purpose: images `![]()` (the app makes no network calls, `SEGURANCA.md`; the line stays text), fenced code blocks, tables and footnotes (they need several lines in one block), heading levels 5 and 6 and the horizontal rule `---` (the spec defines four levels; a rule is a line with no text). Numbered lists are not renumbered: the typed number is the value. Formatting never crosses lines. Inline code is parsed first and takes its content raw; the renderer builds React elements only (`<code>`, `<del>`), never HTML. The toolbar and shortcuts act on the line with the cursor, or the section's last line when none has it; multi-line selections are not formatted together. The Markdown checklist `- [ ] ` / `- [x] ` is detected by `detectKind` as a task (the product side is in `spec/nota-do-dia.md`, "Formatação"). Auto-pairing of `**`, `` ` ``, `[]` and `()` is not done.
**Why:** Each item is either already blocked by the block model (one line, one block), by the local-only rules, or costs more surprise than it saves: renumbering would rewrite lines the person did not touch, a toolbar that formats a multi-line selection needs a rule for lines of different kinds, and auto-pairing fights the markers typed one at a time (`[] `, `**`).
